This page documents every method exported by `@actual-app/api`. All methods are `async` and return a `Promise` unless noted otherwise. Call `init` and `loadBudget` (or `downloadBudget`) before using any other method.

---

## Budget management

### `init`

Boots the loot-core engine and sets up the local data directory. Must be called before any other method.

```typescript
async function init(config?: InitConfig): Promise<lib>
```

<ParamField path="config.dataDir" type="string" optional>
  Path to the directory where budget files are stored. Defaults to the current
  working directory or `ACTUAL_DATA_DIR` environment variable.
</ParamField>
<ParamField path="config.serverURL" type="string" optional>
  URL of an Actual server to connect to for downloading and syncing budgets.
</ParamField>
<ParamField path="config.password" type="string" optional>
  Password for server authentication. Mutually exclusive with `sessionToken`.
</ParamField>
<ParamField path="config.sessionToken" type="string" optional>
  Session token for server authentication. Mutually exclusive with `password`.
</ParamField>
<ParamField path="config.verbose" type="boolean" optional>
  Enable verbose logging from the loot-core engine.
</ParamField>

---

### `shutdown`

Syncs pending changes, closes the open budget, and shuts down the engine. Always call this when your script finishes.

```typescript
async function shutdown(): Promise<void>
```

### `getBudgets`

```typescript

```

Each entry has at minimum `id`, `name`, and `cloudFileId`.

### `loadBudget`

```typescript
async function loadBudget(budgetId: string): Promise<void>
```

<ParamField path="budgetId" type="string" required>
  The local ID of the budget to open. Use `getBudgets` to list available IDs.

### `downloadBudget`

Downloads a budget from the connected Actual server and loads it. Requires `serverURL` to be set in `init`.

```typescript
async function downloadBudget(
  syncId: string,
  options?: { password?: string },
): Promise<void>
```

<ParamField path="syncId" type="string" required>
  The sync (cloud) ID of the budget on the server.
</ParamField>
<ParamField path="options.password" type="string" optional>
  Decryption password if the budget is end-to-end encrypted.
</ParamField>

### `sync`

```typescript
async function sync(): Promise<void>
```

### `runBankSync`

Triggers an automatic bank sync (SimpleFin, GoCardless, or Pluggy) for one or all connected accounts.

```typescript
async function runBankSync(args?: { accountId: string }): Promise<void>
```

<ParamField path="args.accountId" type="string" optional>
  ID of a specific account to sync. Omit to sync all bank-connected accounts.

---

### `runImport`

Wraps a function in an import transaction. The function is called between `api/start-import` and `api/finish-import` signals, which lets the engine optimise writes. If the function throws, the import is aborted.

```typescript
async function runImport(
  budgetName: string,
  func: () => Promise<void>,
): Promise<void>
```

<ParamField path="budgetName" type="string" required>
  Name for the new budget being imported.
</ParamField>
<ParamField path="func" type="() => Promise<void>" required>
  Async function that performs the import. Call API methods inside this
  function.
</ParamField>

### `batchBudgetUpdates`

Wraps multiple budget-month writes in a single batch for better performance. Use this when setting many amounts at once.

```typescript
async function batchBudgetUpdates(func: () => Promise<void>): Promise<void>
```

<ParamField path="func" type="() => Promise<void>" required>
  Async function that calls `setBudgetAmount`, `setBudgetCarryover`, or related
  methods.
</ParamField>

```typescript
await api.batchBudgetUpdates(async () => {
  await api.setBudgetAmount('2024-03', categoryId, 5000);
  await api.setBudgetAmount('2024-03', otherCategoryId, 10000);
});
```

### `addTransactions`

Adds new transactions to an account without running the deduplication or reconciliation logic that `importTransactions` applies.

```typescript

  accountId: string,
  transactions: Omit<ImportTransactionEntity, 'account'>[],
  options?: { learnCategories?: boolean; runTransfers?: boolean },
): Promise<string[]>
```

<ParamField path="accountId" type="string" required>
  ID of the account to add transactions to.
</ParamField>
<ParamField path="transactions" type="Omit<ImportTransactionEntity, 'account'>[]" required>
  Array of transaction objects. See `ImportTransactionEntity` fields below.
</ParamField>
<ParamField path="options.learnCategories" type="boolean" optional defaultValue="false">
  If `true`, the rules engine learns category assignments from these
  transactions.
</ParamField>
<ParamField path="options.runTransfers" type="boolean" optional defaultValue="false">
  If `true`, transfer matching is run against existing transactions.
</ParamField>

---

### `importTransactions`

Imports transactions with full deduplication (via `imported_id`), transfer matching, and reconciliation. Prefer this over `addTransactions` when importing from a bank or file.

```typescript
async function importTransactions(
  accountId: string,
  transactions: ImportTransactionEntity[],
  opts?: { defaultCleared?: boolean; dryRun?: boolean },
): Promise<{ added: string[]; updated: string[] }>
```

<ParamField path="accountId" type="string" required>
  ID of the account to import into.
</ParamField>
<ParamField path="transactions" type="ImportTransactionEntity[]" required>
  Array of transactions. Each must include `account`, `date`, and optionally
  `amount`, `payee`, `payee_name`, `imported_payee`, `category`, `notes`,
  `imported_id`, `cleared`, and `subtransactions`.
</ParamField>
<ParamField path="opts.defaultCleared" type="boolean" optional defaultValue="true">
  Mark imported transactions as cleared by default.
</ParamField>
<ParamField path="opts.dryRun" type="boolean" optional defaultValue="false">
  If `true`, preview changes without saving them.
</ParamField>

## Utilities

### `aqlQuery`

Executes an AQL query built with the `q` helper. Returns the raw result set.

```typescript
async function aqlQuery(query: Query): Promise<{ data: unknown[]; total: number }>
```

<ParamField path="query" type="Query" required>
  A `Query` object built with the `q` helper.
</ParamField>

```typescript
import { q, aqlQuery } from '@actual-app/api';

const result = await aqlQuery(
  q('transactions')
    .filter({ account: accountId, date: { $gte: '2024-01-01' } })
    .select(['date', 'amount', 'payee', 'category'])
    .orderBy({ date: 'desc' })
);

console.log(result.data);
```

---

### `q`

Creates a new `Query` object targeting the specified table. Chain methods to build the query, then pass it to `aqlQuery`.

```typescript
function q(table: string): Query
```

<ParamField path="table" type="string" required>
  The data table to query. Common values: `'transactions'`, `'accounts'`,
  `'categories'`, `'payees'`.
</ParamField>

The returned `Query` supports the following chainable methods:

| Method | Description |
|--------|-------------|
| `.filter(expr)` | Add a filter expression |
| `.select(fields)` | Select specific fields or `'*'` |
| `.calculate(expr)` | Run an aggregate calculation |
| `.groupBy(fields)` | Group results by fields |
| `.orderBy(fields)` | Order results |
| `.limit(n)` | Limit the number of results |
| `.offset(n)` | Skip the first `n` results |
| `.raw()` | Return raw (unconverted) values |
| `.withDead()` | Include soft-deleted records |
